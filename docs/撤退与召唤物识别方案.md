# 撤退与召唤物识别方案

> 目标：在「视频 → copilot」流水线里补上两块能力
> ① 识别**召唤物 / 装置**（障碍物、无人机等）
> ② 识别**撤退**事件
>
> 本文所有机制都从 MAA 源码核实，所有坐标/阈值都标注是「实测」还是「待标定」。

---

## 1. 核心思路：撤退不需要知道是谁

这是整个方案的关键简化。

```jsonc
// 老思路：要认出"是德克萨斯撤退了" → 需要身份识别 → 卡在名字 OCR
{ "type": "Retreat", "name": "德克萨斯" }

// 新思路：只说"这个格子上的东西撤了"
{ "type": "Retreat", "location": [7, 5] }
```

因为 `CopilotConfig.cpp:348-353` 明确 **location 优先**，MAA 拿到 location 就直接
`retreat_oper(loc)` → 点该格像素 → 点撤退按钮，**完全不碰 `m_battlefield_opers` 的按名查找**。

⇒ **撤退检测只需要"某格子的干员消失了"，不需要知道名字。**

同样地，召唤物只需要：
- 知道它是召唤物（编队栏职业图标 = Drone）
- 知道落点（白菱形）
- 名字统一写 `障碍物`（MAA 的 BattleData 里有这个条目）或显式 `"role":"召唤物"`

⇒ **整条链路绕开了干员身份识别。**

## 2. 输出形态

```jsonc
{
  "opers": [
    { "name": "障碍物", "role": "召唤物" }
  ],
  "actions": [
    // 召唤物：方向一般 None
    { "type": "Deploy", "name": "障碍物", "role": "召唤物",
      "location": [9, 2], "direction": "None" },

    // 撤退：只给 location
    { "type": "Retreat", "location": [7, 5] }
  ]
}
```

> `role` 在 actions 里也生效（事实 #2），所以召唤物动作可以显式带 `role`，
> 不必依赖 BattleData 把 TRAP 类默认成 Drone。

## 3. 流程 A —— 召唤物 / 装置识别

### 输入
编队栏里含召唤物卡的视频（例如 EX-3 那种要放障碍物的关卡）。

### 步骤

**A1 找放置瞬间**
复用现有：`deploy.scanBarChanges()` 每 1.5s 比对编队栏色块 → 得到部署窗口。
实测 YW-1-B：22.0s / 23.5s 两次变动。

**A2 找落点 = 白菱形**（不是橙色斜纹）

实测特征（YW-1-B @24.3s）：白色细边框、正方形但斜置 45°（菱形）、
边长≈1 格宽、边框粗 2~3px、内部透明可看到地面。

落地算法（逐格检查，和 `posmask` 同思路）：
```
对每个格子 (tx,ty)：
  沿该格四条边的中点取采样点（不用格心，避免地面纹理干扰）
  统计亮白像素占比白亮度 >200 且饱和度低
  四条边都明显有白 → 该格被菱形框住 → 它是落点
```
*为什么用边不用心*：菱形是**框**，中心是空的。用中心采不到。

**待标定**：菱形边框的精确亮度/粗度，需要先截几帧量。

**A3 判类型：读编队栏职业图标**
```
对每张卡：
  取角色图标区 31×25（1280 基准，rectMove [-41,6,31,25]）
  与 9 个 BattleOperRole*.png 做 NCC（MAA 阈值 0.65；我实测过 0.62 说明区域要重标）
  Drone 图标 → 召唤物
  其他 8 种  → 干员
```
这一步**同时解决了"这张卡是不是召唤物"和"卡在哪"**。

**A4 朝向**
- 召唤物/装置：`"None"`（MAA 枚举里有 `None`，注释写明"没有方向，通常是无人机之类的"）
- 如果视频里能看到拖拽向量，也可以用拖拽方向

**A5 输出**

### 判定表

| 编队栏职业图标 | 落到哪 | 输出 |
|---|---|---|
| `BattleOperRoleDrone` | 白菱形格 | `Deploy, role:召唤物, direction:None` |
| 其他 8 种 | 白菱形格 | `Deploy, name:干员名, direction:拖拽方向` |

### 关于名字
- 召唤物统一写 `障碍物`（BattleData 里 `position=NONE / profession=TRAP`，MAA 会归到 Drone）
- 或显式 `"role":"召唤物"`，不依赖默认值 —— **推荐这个**

## 4. 流程 B —— 撤退识别

### B1 建立已部署清单
复用现有 placement events：`{格子, 落地时刻}`。
（落点用白菱形，不用橙色斜纹。）

### B2 逐格测「占位度」`occ(t)`

```
对每个已部署格 (tx,ty)：
  采样区 = 格心上方一块（宽 ≈0.8 格、高 ≈1.2 格）
          [因为精灵画在格心上方，脚底才在格心 —— 实测偏差 36~40px]
  参考帧 = 该格「部署之前」的几帧（每格自己的空场参考）
  occ(t) = 当前帧与参考帧在该区域的差异像素占比
```

**为什么用参考帧而不是固定阈值**：地图本身颜色差异极大（水面/石板/高台），
固定阈值没法跨格通用。逐格取自己的空场参考最稳。

### B3 事件判定

```
occ 从 ≥0.15 降到 ≤0.05
且持续 ≥3 个采样点（1fps → 3 秒）
→ 判定为「撤退」，记录时刻 T 和格子
```

**采样率 1fps 就够**：撤退是秒级事件，不需要 30fps。

### B4 反向校验（可选但建议）
查编队栏对应卡片是否变灰（cooling，`BattleOperCooling` 那条 114×4 细条数色）。
变灰 ⇒ 该干员确实不在了 ⇒ 提高置信度。

⚠ **MAA 自己也分不清撤退和死亡**（两者头像都变灰、精灵都消失）。
所以我们也分不清，方案里当同一种事件处理。

### B5 输出

按时间顺序把 `Retreat` 插进 actions 序列：

```jsonc
{ "type": "Retreat", "location": [7, 5] }
```

### 关于「死亡」的兜底
如果视频里那个干员是**被打死**而不是撤退的，我们发的 Retreat 会点到空格子。
MAA 的 `retreat_oper` 里有：
```cpp
cancel_oper_selection(); // 兜底一下, 防止格子上面并没有干员, 导致点到隔壁格子
```
⇒ 点到空格不会崩，只是浪费一次点击 + 一次 `cancel_oper_selection`。
**可接受，但要在文档里写明。**

## 6. 验证方法（不需要真机）

### 6.1 召唤物检测 —— 有现成的地面真值！

**`F:\dspet\video\YW-EX-3-突袭.mp4` + PRTSPlus 作业 = 已知答案**：

```jsonc
// PRTSPlus_昨日海 - YW-EX-3 兼容一摆到底.json
{ "name": "障碍物", "type": "Deploy", "location": [9, 2], "direction": "None" },
{ "name": "障碍物", "type": "Deploy", "location": [7, 3], "direction": "None" }
```

**两个障碍物，位置和方向都已知。** 可以直接拿它验我的召唤物检测器：
- 能不能检出 2 个召唤物落点
- 检出的格子是不是 [9,2] 和 [7,3]
- 判定的类型是不是"召唤物"

⚠ 注意：这份视频**跑不了 MAA**（MAA 没有 `act52side_ex03` 的地图数据），
但**验证检测器完全够用** —— 检测器只需要视频和坐标，不需要地图数据。
（唯一影响：`tileproj` 算不出 EX-3 的格心像素，所以 EX-3 上只能用
"相对地图框架"目测比对，不能用投影反查。这点要说清楚。）

### 6.2 撤退检测 —— 需要找一段有撤退的视频

需要一个「有干员被撤掉」的样本。可以用：
- 任意一关"换人"操作的视频
- 或 MAA 的 `resource/copilot/` 里带 `Retreat` 动作的作业 + 对应视频

## 7. 关键风险与兜底

| 风险 | 影响 | 兜底 |
|---|---|---|
| 白菱形对比度不足（浅色地图） | 落点检测失败 | 退回"脚底像素 + 精灵占位检测"；或 `rangefit.fitAnchor` 反解锚点 |
| 撤退/死亡混淆 | 多发一次 Retreat | MAA 有 `cancel_oper_selection` 兜底，只浪费一次点击 |
| 地图会平移（放干员时） | 参考帧对不齐 → occ 误判 | **只在"部署动作完成后、地图稳定"的帧间比**；每格参考帧取静置段 |
| 召唤物视频样本少 | 调不准 | 用 EX-3 那份已知答案的视频校，命中 [9,2]/[7,3] 才算过 |
| 编队栏卡片会重排 | 职业图标取错卡 | 按**卡片锚点**取（不是固定 x），锚点从旗标检测来 |

## 9. 与现有流水线的关系

```
现有（已可用）:
  战斗起点 → 部署窗口 → 落点(橙斜纹,不可靠) → 朝向 → 站位类型 → 干员名 → 技能

本方案替换/新增:
  落点：橙色斜纹  →  白菱形          （替换，更可靠）
  新增：编队栏职业图标 → 召唤物判别
  新增：逐格占位度 → 撤退事件
  保留：tileproj / copilot 校验 / annotate / opername（干员名仍可用于非召唤物）
```

**注意：橙色斜纹那条路要被替换掉。** 实测它既不是标记也不是范围（11 格、外溢 387%），
继续用它只会产出"不对应任何干员"的假标记——就是之前被指出的问题。
